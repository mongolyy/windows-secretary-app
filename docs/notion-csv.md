# NotionのCSVを秘書アプリで読む

このアプリは Notion の API も MCP も使いません。ネットワークで Notion に接続しません。利用者が Notion の画面から自分で書き出した CSV を、PC の中だけで読みます。

会議の URL を開くときだけ、利用者が「参加する」を押した場合に OS のブラウザが起動します。アプリ自身はページを取得しません。

## 書き出し

1. 予定の入った Notion データベースを開きます。
2. 表示しているビューに、今日から先の予定が入っていることを確認します。過去の行が混ざっていてもかまいません。アプリは終わった予定を一覧から外します。
3. 右上の `…` メニューから **エクスポート** を選びます（英語 UI では Export）。
4. 形式は **CSV** にします。
5. エクスポートを作成してダウンロードします。

Notion は結果を ZIP にまとめることがあります。このアプリは ZIP を開きません。展開して、中の `.csv`（データベース名がファイル名になっていることが多いです）を指定してください。

Excel で開き直して保存し直すと、文字コードや区切りが変わることがあります。Notion が書いた CSV を、そのまま指定してください。

## ファイルの場所と更新

初期のパスは次です。

`%USERPROFILE%\secretary\schedule.csv`

設定で別のパスを選べます。開発時だけ、環境変数 `SECRETARY_SCHEDULE_PATH` が設定ファイルより優先されます。

同じパスへ上書きすると、アプリが変更を検知して読み直します。エクスポートのたびに `予定 (1).csv` のような新しい名前になる場合は、設定で選び直してください。

開始前の通知は、タイトルと開始時刻が同じ予定には一度だけ出します。開始時刻を変えて同じパスへ上書きすると、新しい時刻で知らせます。通知のための通信はありません。

書き出しは、可能なら同じファイルを置き換えてください。アプリは親フォルダを監視し、連続した変更は少し間を置いてから読みます。

## 文字コード

UTF-8 です。先頭の BOM（Notion の書き出しについている `EF BB BF`）はあってもなくても読めます。UTF-16 の BOM が付いているファイルも読めます。5MB を超えるファイルは拒否します。

1行目は見出しです。Excel が付ける `sep=,` だけの行は無視します。

## 列の対応

データベースごとに列名が違います。初期状態では列名を自動判定します。判定できなければ設定で列名を指定し、「列名を自動で判定する」を外してください。

| 役割 | わかるとみなす名前（大文字小文字、空白、アンダースコアは無視） |
| --- | --- |
| タイトル | 名前, Name, タイトル, Title, 件名, 予定名, タスク名, 名称, 予定, タスク, 内容 |
| 日時 | 日付, Date, 日時, 開始日時, 実施日時, 予定日, 実施日, 開始日, Start, Start Time, When, 時間, 開始 |
| 終了（任意） | 終了, 終了日時, 終了日, End, End Time, 終わり |
| 場所（任意） | 場所, 会場, 会議室, Location, Place, Where, 所在地, 部屋, Room |
| URL（任意） | URL, リンク, Link, 会議リンク, 参加リンク, 会議URL, 参加URL, Meet |

日時の列名が上のどれでもないときは、中身が日付として読める列を探します。タイトルが見つからないときは、日時以外の先頭の列をタイトルにします。

終了列は空で構いません。Notion の日付プロパティは、開始と終了を **1つのセル** に入れることが多いです。日時セルにすでに期間が入っているときは、終了列があっても使いません。日時セルが開始だけで、終了列に終わりが入っているときは、二つをつないで読みます。

使わない列（タグなど）は無視します。未知の列が増えても、必要な列が残っていれば読めます。

「この判定を固定」を押すと、いま使っている列名が設定に入り、自動判定が外れます。

## 日付の書式

ゾーンの書いていない時刻は、設定のタイムゾーンで解釈します。初期値は **Asia/Tokyo**（日本時間、夏時間なし）です。PC のタイムゾーンが違っていても、初期設定のままなら日本時間として読まれます。

セルに `(GMT+9)` や `(GMT-5)`、`(GMT+05:30)`、`(JST)`、`(UTC)` が付いているときは、その側だけオフセットを使います。終了時刻だけ書いてありゾーンがないときは、開始側のゾーンを引き継ぎます。

区切りは Notion が書く `→`（U+2192）です。`->`、`⇒`、エンダッシュ、エムダッシュも受けます。

### 時刻のある予定

終了の瞬間に予定は終わります。進行中なのは「開始 ≦ いま ＜ 終了」のあいだです。

英語の例:

```text
November 19, 2026 10:00 AM → November 19, 2026 10:30 AM
November 19, 2026 10:00 AM → 10:30 AM
November 19, 2026 10:00 AM (GMT+9) → 10:30 AM
Thursday, November 19, 2026 3:05 PM
```

日本語の例:

```text
2026年11月19日 10:00 → 10:30
2026年11月19日 10:00 → 2026年11月19日 10:30
2026年11月19日（木） 10:00 (GMT+9) → 10:30
2026年11月19日 午後3:05 → 午後4:00
```

同じ日の終了時刻だけが書いてあり、その時刻が開始以前なら翌日とみなします。例: `23:00 → 1:00` は翌日の 1:00 までです。日付まで書いてあって終了が開始以前のときは、その行を読み飛ばします。

時刻が一つだけで終了がないときは、1時間の予定として扱います。

`12:00 AM` は 0:00、`12:00 PM` は 12:00 です。月名は `November` のほか `Nov` のような省略も読めます。全角数字と全角コロンも読めます。

ほかに `2026-11-19T10:00:00+09:00` と `2026/11/19 10:00` も読めます。

### 終日

日付だけで時刻がないセルは終日です。Notion の終了日は、その日を含みます。

```text
2026年11月19日
2026年11月18日 → 2026年11月19日
November 19, 2026
November 18, 2026 → November 19, 2026
```

`11月18日 → 11月19日` は 18日と 19日の両方です。アプリの内部では、終わりを「終了日の翌日 0:00」として持っています。同じ日を両側に書いた `11月19日 → 11月19日` も、その1日です。

## 画面での扱い

タイムゾーンは設定のものです（初期値は日本時間）。

- **進行中**: いま時刻指定の予定が重なっているとき、いちばん早く終わるものを大きく出します。表示は終了までのカウントダウンです。
- **終日**: 今日かかっている終日予定は帯で出します。時刻指定の進行中がなければ、終日予定を主表示にします。カウントダウンは出しません。
- **次の予定**: まだ始まっていない予定のうち、いちばん早いものです。終日予定と同じ期間に始まる時刻指定の予定があるときは、その終日は「次」にしません。深夜0時の終日が、同じ日の会議を隠さないためです。時刻指定が一つも残っていなければ、次の終日を出します。
- **本日の残り**: 今日（設定タイムゾーンの暦日）にかかっていて、まだ終わっておらず、上のカードに出していない時刻指定の予定です。

終わった予定は出しません。行の順番は関係ありません。

## 古さの警告

CSV には書き出し時刻の列がありません。ファイルの更新日時と比べます。初期値は **24時間（1440分）** です。設定で 5分から 20160分（14日）まで変えられます。しきい値を超えると、予定は出したまま、黄色い注意を出します。

予定が変わったら、同じパスへ書き出してください。ファイルを触らずに中身だけ古くなることは、更新日時では検知できません。

## 読み飛ばす行

日付が空、形式が読めない、終了が開始以前、の行は飛ばして、ほかの行は表示します。URL が `http` か `https` でないときは、予定は残してリンクだけ捨てます。すべてのデータ行が読めないときは、ファイル全体を形式エラーにします。見出しだけのファイルは「予定がありません」です。

タイトルが空の行は「（無題）」にします。

読み込みの途中でファイルが壊れて見えたときは、直前に読めた予定を残し、その旨を表示します。ファイルが無くなったときは、無いものとして表示します。

## サンプル

- `samples/notion-ja.csv` … 日本語の日付
- `samples/notion-en.csv` … 英語の日付

どちらも同じ時刻の予定です。先頭に UTF-8 BOM を付けてあります。開発中にパスへコピーするか、ブラウザの `npm run dev` でサンプルを表示できます。
